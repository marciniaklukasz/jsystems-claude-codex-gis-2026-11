## 3. API `app/src/map_qa/vision.py` (zależy tylko od `config`, `store`; NIE importuj `evaluation`, `compare`, `matching`)
- `questions_for_stage(th, stage) -> dict[qid, dict]` — pytania z `th["questions"]` o `stage <= stage`, kolejność jak w TOML. `options(th, qid) -> list[str]` (klucze `criteria`).
- `class ImageRejected(Exception)`; `@dataclass PreparedImage(data: bytes, sha256: str, width: int, height: int)`; `prepare_image(path, th) -> PreparedImage` — Pillow; format musi być JPEG lub PNG, krótszy bok ≥ `min_side_px`; dłuższy bok > `max_side_px` → proporcjonalnie do `max_side_px` (LANCZOS, JPEG quality 90, `round`); inaczej bajty bez zmian. `sha256` z wysyłanych bajtów.
- `build_decisions_request(qid, th, image_bytes) -> dict` z kluczami **dokładnie** `state`, `questions`, `provider`: `state = [{"type":"text","text": th["vision"]["state_text"]}, {"type":"image_url","image_url":{"url":"data:image/jpeg;base64,<b64>"}}]` (PNG → `image/png`), `questions = {qid: {"type":"choice","instructions": ..., "criteria": dict(...)}}`, `provider = {"allow_fallbacks": False}`. Model dokłada wywołujący (`{"model": ..., **req}`).
- `build_chat_request(qid, th, image_bytes) -> dict` — klucze `messages`, `reasoning`, `max_tokens`, `response_format`, `provider`; jak w `capture_openrouter.py` (jedna wiadomość `user`: tekst = `state_text` + instrukcja + lista opcji z opisami; potem `image_url`; `reasoning={"effort": fallback_reasoning_effort}`; `response_format` JSON Schema strict z `answer` ∈ opcje; `provider={"require_parameters": True, "allow_fallbacks": False}`).
- `@dataclass DecisionReading(answer: str|None, probability: float|None, confident: bool)`; `interpret_decision(body, qid, options, threshold) -> DecisionReading` — `answers[qid].choice` ∈ opcje, ≠ `unknown`, `max(probabilities.values()) >= threshold` → confident; brak pytania/choice spoza listy/brak prawdopodobieństw → not confident.
- `@dataclass ChatReading(answer: str|None, status: str)`; `interpret_chat(body, options)` — `choices[0].message.content` jako JSON `{"answer": ...}`: w opcjach i ≠ `unknown` → `certain`; `unknown` → `abstain`; pusta treść, zły JSON, spoza listy, brak pól → `model_unavailable`.
- `cost_of(body) -> float|None` = `max(usage.cost, usage.cost_details.upstream_inference_cost)` z dostępnych; brak obu → `None`.
- `class TransportError(Exception)` z `.status: int|None` i `.kind: str`, konstruktor `TransportError(status, kind)`.
- `class OpenRouterTransport` — `__init__(api_key, timeout_s=40, http_client=None)`; atrybuty `client` (SDK `OpenRouter`), `retry` (`RetryConfig("none", BackoffStrategy(500, 60000, 1.5, 3600000), False)`), `timeout_ms`. `http_client` domyślnie `httpx.Client()`; dodaj event hook na odpowiedź, który czyta i zapamiętuje surowe ciało JSON i status ostatniej odpowiedzi. `__call__(endpoint, payload)`: `"decisions"` → `client.alpha.decisions.create(**payload, retries=self.retry, timeout_ms=self.timeout_ms)`, `"chat"` → `client.chat.send(**payload, retries=..., timeout_ms=...)`; zwraca **surowe ciało** (dict z hooka). Każdy wyjątek (SDK, httpx, walidacja) albo status ≥ 400 → `TransportError(status lub None, nazwa klasy)`. Klucz API nigdy w komunikatach.
- `split_of(sequence) -> "validation"|"test"` — pierwszy bajt `sha256(sequence.encode())` parzysty → walidacja.
- `select_pairs(labels_df, qids, limit) -> DataFrame` — `labels_df` kolumny `photo_id, question_id, label, status, sequence` (+ opcjonalnie `image_path`); tylko `status == "certain"` i `question_id ∈ qids`; per pytanie sortowanie po `sha256(photo_id + question_id)` hex; naprzemiennie w kolejności `qids`, aż do `limit` (gdy pytanie się skończy — dalej pozostałe); kolumny wyniku `photo_id, question_id, split, sequence, order` (+ `image_path` jeśli było), `order` = 0..n-1.
- `@dataclass Sample(manifest: DataFrame, images: dict[sha256, bytes], excluded: dict[str,int], attribution: dict, photo_paths: dict)`; `build_sample(stage, limit, th, data_dir, labels) -> Sample` — `labels` jak z `evaluation.load_labels(data_dir)` (kolumny `photo_id, question_id, label, status, sequence, image_path, author, license, source_url`). Zdjęcie bez pliku (`image_path` None/nieistniejący) albo `ImageRejected` → pomijane z licznikiem w `excluded` (powód po polsku) i bierzemy kolejną parę; manifest ma `image_sha256` (64 hex) i nie więcej niż `limit` par. `images` mapuje sha → bajty do wysłania. `attribution[photo_id] = {author, license, source_url, local_path}`.
- `write_manifest(manifest, run_dir) -> Path` — `run_dir/"sample_manifest.csv"` (kolumny `photo_id, question_id, split, sequence, image_sha256, order`), `flush` + `os.fsync` przed powrotem.
- `@dataclass CascadeResult(readings: DataFrame, comparison: DataFrame, usage: dict, cost_total_usd: float, requests_total: int)`.
- `run_cascade(conn, *, run_id, manifest, images, links, limits, th, transport) -> CascadeResult` — dla każdej pary w kolejności `order` (ADR-002 §4.3–4.9, diagramy §7):
  1. `cache_get(sha, decision_model, qid, questions_version)` → trafienie bez żądania (`cache_hit=True`); inaczej `budget_reserve(conn, run_id, model, limit=limits.decision, max_cost=limits.max_cost_usd, reserve=th["vision"]["reserve_usd"])` → odmowa = brak odczytu; zgoda → `transport("decisions", {"model": m, **build_decisions_request(...)})`; błąd → `budget_record(..., cost_usd=None, error=True, disable=True)` (model wyłączony do końca runu, AC-20); sukces → `budget_record(..., cost_usd=cost_of(body), error=False)` i `cache_put(..., response=body, reading={...})` (błędów nie cache'ujemy).
  2. Pewny = `interpret_decision(...).confident` **i** `links.get(photo_id) != "uncertain"` (`None`/brak = brak pary z mapą → warunek połączenia nie dotyczy). Pewny → `final_stage="decision"`, `status="certain"`, `model=decision_model`.
  3. Inaczej jedna eskalacja: cache dla `fallback_model`; potem `budget_reserve(limit=limits.fallback)`; odmowa → `manual` + `model_unavailable`; `transport("chat", ...)`; błąd → `model_unavailable` (+ wyłączenie modelu); `interpret_chat` → `certain` (`final_stage="fallback"`, `model=fallback_model`), `abstain` → `manual`+`abstain`, `model_unavailable` → `manual`+`model_unavailable`.
  4. Model porównawczy (`comparison_model`): po parze, która **faktycznie została wysłana** do modelu głównego w tym runie (nie z cache) i tylko dopóki model główny nie jest wyłączony i `sent < limits.comparison` — `transport("decisions", ...)` z tym samym żądaniem; wynik tylko do `comparison` (kolumny `photo_id, question_id, split, model, answer, probability, confident`); bez wpływu na odczyt i eskalację. Cache również dla porównawczego.
  5. Żaden wyjątek nie wychodzi z `run_cascade` (`TransportError`, `TimeoutError`, `RuntimeError` itd. → błąd modelu).
  Kolumny `readings`: `photo_id, question_id, split, final_stage, model, answer, probability, status, reason, decision_answer, decision_probability, decision_confident, fallback_answer, cache_hit, link_status, image_sha256, cost_usd` (`model=""` dla `manual`; `reason` = `status` dla manual, inaczej `""`).
  `usage = store.budget_usage(conn, run_id)`, `cost_total_usd` = suma `cost_usd` z usage, `requests_total` = suma `sent`.
- `vision_summary(readings) -> {qid: {"decision", "fallback", "manual", "total"}}`.
- `run_vision(conn, *, run_id, stage, limits, th, layers, assessment, data_dir, run_dir, labels, sign_links=None, transport=None) -> dict` — używane przez `cli`:
  - limity 0 → bez manifestu i żądań; zwróć `{"readings": pusty DataFrame z kolumnami jak wyżej, "comparison": [], "usage": {}, "cost_total_usd": 0.0, "requests_total": 0, "vision_summary": {}, "openrouter_state": "brak budżetu (limity 0) — ...", "photo_paths": {}, "attribution": {}}`.
  - limit > 0: `build_sample(stage, limits.decision, ...)`, `write_manifest` **przed** pierwszym żądaniem; `links` = `{photo_id: status}` z `assessment` (`certain`/`uncertain`) oraz z `sign_links` (DataFrame z `matching.assess_sign_links`; `evaluation_only` → brak klucza); transport domyślnie `OpenRouterTransport(os.environ["OPENROUTER_API_KEY"], th["vision"]["timeout_s"])`; brak zmiennej → wszystkie pary `manual`/`model_unavailable`, 0 żądań, stan „brak klucza OPENROUTER_API_KEY”; inaczej `run_cascade`. Stan OpenRouter: liczba żądań, błędy (nazwa modelu i liczba), koszt. Zwraca słownik jak wyżej + `comparison` (lista dictów) i `vision_summary`.
