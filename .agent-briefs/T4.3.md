## 2. Kontrakt
- ADR-003 §3.1, §4, §5, D-301 (`docs/ADR/003-raport-i-dashboard.md`); PRD §9.2 i AC-03–AC-05, AC-08, AC-09, AC-14–AC-16, AC-20e, AC-20f, AC-23–AC-26 (`docs/PRD.md`).
- Wejście runu (pliki w `run_dir`): `candidates.parquet` (kolumny jak w teście `_cand`: lista z ADR-001 §4.5 + `candidate_id`, `candidate_key`, `run_id`, `stage`, `osm_url`, `highway`, `name`, `osm_status`, `overture_status`, `link_status`, `osm_extract_date`), `readings.parquet` (może być pusty), `run.json` (klucze jak `RUN` w teście).

API `app/src/map_qa/report.py`:
- `write_report(run_dir: Path, verify: Callable[[], None] | None = None) -> dict[str, Path]` — klucze `"md"`, `"html"`, `"csv"` → `report.md`, `report.html`, `candidates.csv`.
  1. Wczytaj `run.json` (brak → `FileNotFoundError`), `candidates.parquet`, `readings.parquet`.
  2. Lista szczegółowa = kandydaci z kategorią `rozbieżne` i `do sprawdzenia`, kolejność: `rozbieżne` przed `do sprawdzenia`, potem `attribute`, potem `osm_id` rosnąco. Ta sama lista we wszystkich 3 formatach.
  3. Wyrenderuj do plików `*.tmp` w `run_dir` (`_render_md(ctx) -> str`, `_render_html(ctx) -> str` — te nazwy funkcji są wymagane, test podmienia `_render_html`), CSV przez pandas `to_csv(..., index=False, encoding="utf-8-sig")` (BOM, separator `,`), listy (`overture_ids`, `photo_ids`, `link_status`, `reasons`) jako tekst JSON (`json.dumps(list, ensure_ascii=False)`).
  4. Wywołaj `verify()` jeśli podano (końcowa kontrola hashy wejść, AC-01).
  5. Dopiero potem zmień nazwy `*.tmp` → docelowe. **Każdy wyjątek w krokach 3–5 → usuń wszystkie `*.tmp` i docelowe pliki utworzone w tym wywołaniu, potem rzuć dalej** (brak częściowego raportu).
- Szablony Jinja2 w `app/src/map_qa/templates/report.md.j2` i `report.html.j2`, ładowane `PackageLoader("map_qa", "templates")` albo `FileSystemLoader` względem `__file__`. **Autoescape tylko dla HTML** (`select_autoescape(["html", "j2"])` nie wystarczy dla `.html.j2` — użyj osobnego `Environment(autoescape=True)` dla HTML i `autoescape=False` dla MD). HTML jeden plik, style inline w `<style>`, bez zewnętrznych skryptów, fontów i `<link>`.
- Każdy wiersz listy w HTML: `<tr class="candidate">`; w MD wiersz tabeli zaczynający się od `| ` i zawierający `candidate_id`.

Treść (po polsku; identyfikatory i surowe tagi bez tłumaczenia):
- Nagłówek: data kontroli (`created_at`), `run_id`, etap, użyty CRS (`crs`), „Wersja pytań: <questions_version>”, hash commitu progów (`thresholds_commit`), tabela źródeł (`sources`: nazwa, wersja, data, licencja).
- Liczności wejść z separatorem tysięcy spacją niełamliwą lub zwykłą (`99 768`), np. filtr Jinja `thousands`.
- Połączenia zdjęć (AC-09): pewne / niepewne / bez kandydata / razem, oraz „zdjęcia bez kierunku: N” (tekst „bez kierunku”).
- Podsumowanie: tabela `| atrybut | zgodne | rozbieżne | do sprawdzenia |` po atrybucie z polską etykietą (`speed` → „ograniczenie prędkości”, `surface` → „nawierzchnia”, `lit` → „oświetlenie”, `junction` → „skrzyżowanie”), liczone ze **wszystkich** kandydatów (także `zgodne`). Wiersz MD dokładnie w formie `| ograniczenie prędkości | 3 | 1 | 3 |`.
- Liczniki wykluczeń (`exclusions`): powód → liczba.
- Sekcja „Ograniczenia”: każdy wpis `limitations` jako „<source>: <reason>”.
- Modele (TAC-002-03, AC-20e): gdy `usage` niepuste — tabela model → wysłane żądania, błędy, koszt USD (4 miejsca po przecinku, kropka dziesiętna, np. `0.0012`), łączny koszt `cost_total_usd` i liczba żądań; tabela `vision_summary` per pytanie z kolumnami „model decyzyjny”, „drugi stopień”, „kolejka ręczna”, „razem”. Gdy puste — „Brak wywołań modelu w tej kontroli.”
- Ewaluacja (AC-23): gdy `evaluation` niepuste — per pytanie: „Trafność” i „pokrycie” z `rows` (split, kto, pary, pewne, poprawne, pokrycie, trafność; `accuracy` None → „brak danych”), plus liczba wykluczonych etykiet `uncertain`.
- Odczyty (AC-20f): gdy `readings` niepuste — tabela photo_id, pytanie, odpowiedź, **stopień** (`final_stage`), model, status, przyczyna.
- Lista kandydatów: kategoria, atrybut, `candidate_id`, OSM id jako odnośnik `osm_url`, nazwa, `overture_ids`, `osm_raw`, `overture_raw`, daty (`osm_timestamp`, `overture_release`), `reasons`, `reason_text`, `photo_reading`, zdjęcia.
- Zdjęcie (AC-25): dla każdego `photo_id` z `photo_attribution` — autor, licencja, odnośnik `source_url`; gdy `local_path` istnieje → miniatura `<img src="<ścieżka względna od run_dir, z / >" width="160">` (MD: `![photo_id](ścieżka)`), inaczej tekst „Zdjęcie niedostępne” + atrybucja. Ścieżka względna przez `os.path.relpath(local_path, run_dir)` z `\` → `/`.
- Stan pusty listy: „Brak kandydatów dla wybranego etapu” + liczności wejść.
- Stopka: „Dane OSM i Overture: ODbL 1.0; zdjęcia: CC BY-SA 4.0 (autorzy przy zdjęciach).”
- **Nigdzie** tekstu „błąd mapy” (AC-14).
