## 2. Kontrakt
ADR-001 §3.2, §3.4, D-101, D-103 (`docs/ADR/001-dane-normalizacja-dopasowanie.md`); reguła kierunku w `course-materials/exercise-data/map-qa/sources.json` → `links.bearing` i `links.ranking`. Nie liczymy połączeń od zera — walidujemy dostarczone.

API (`app/src/map_qa/matching.py`):
- `class CRSError(ValueError)`; `require_metric(gdf)` — `gdf.crs` musi być EPSG:2180, inaczej `CRSError`.
- `angle_diff(heading, bearing) -> float` — różnica nieskierowana 0–90° z zawijaniem 360° (min z d i 180−d po zredukowaniu do 0–180); NaN gdy heading NaN.
- `photo_points_2180(photos: DataFrame) -> GeoDataFrame` (kolumny `longitude`, `latitude`, EPSG:4326 → 2180, `always_xy`).
- `distance_m(point, line) -> float` (geometrie w 2180).
- `local_bearing(line_2180, point_2180, half_length_m) -> float` — rzut punktu na linię (`line.project`), punkty linii w `max(0, s-h)` i `min(L, s+h)` (`interpolate`), przeliczone do EPSG:4326 i **azymut geodezyjny** `pyproj.Geod(ellps="WGS84").inv` (0–360, względem północy rzeczywistej).
- `rank_candidates(df) -> df` — klucz `distance_m + bearing_diff/9` (NaN bearing → +5 m), remis → `distance_m`, potem `osm_id` rosnąco.
- `assess_links(links, photos, osm_2180, th) -> DataFrame` — `require_metric(osm_2180)` na starcie. `osm_2180` ma kolumny `osm_id`, `highway`, `access`, `motor_vehicle` (mogą być None/NaN), `geometry`. `th` to słownik z kluczami jak w `[links]` z `app/config/thresholds.toml`. Wejście `links` jak `photo_road_links.csv` (`osm_way_id` może być `pd.NA`/NaN, `candidate_flags` rozdzielone `;`, puste = brak). `photos` ma `photo_id`, `longitude`, `latitude`, `heading` (NaN = brak).
  Wyjście, wiersz na zdjęcie z `links`: `photo_id`, `osm_way_id`, `overture_id`, `match_method`, `input_flags` (list), `distance_m_input`, `distance_m`, `bearing_diff_input`, `bearing_diff`, `heading_missing` (bool), `status` ∈ {`certain`, `uncertain`, `no_candidate`}, `reasons` (list[str]), `info_flags` (list[str]), `is_uncertain` (bool).
  Reguły (ADR-001 §3.4):
  1. `match_method == "none"` lub flaga `no_osm_within_25m` lub brak `osm_way_id` → `no_candidate`, `reasons=["no_candidate"]`.
  2. Dystans przeliczony w 2180 do geometrii wskazanej drogi; |różnica z `distance_m` wejściowym| > `distance_tolerance_m` → `link_distance_mismatch`.
  3. `bearing_diff = angle_diff(heading, local_bearing(...))`; gdy oba (wejście i wynik) nie są NaN i |różnica| > `bearing_tolerance_deg` → `link_bearing_mismatch`.
  4. Niepewne (`uncertain`) gdy co najmniej jedna przyczyna: `distance_gt_threshold` (dystans przeliczony > `max_distance_m`), `bearing_gt_threshold` (`bearing_diff` > `max_bearing_diff_deg`), flagi wejściowe `ambiguous_candidates`, `overture_spatial_only`, `service_way`, `panorama_heading_ambiguous`, `missing_heading` (każda jako przyczyna o tej samej nazwie), `missing_heading` także gdy heading NaN, `spatial_fallback` (gdy `match_method == "spatial_fallback"`), `link_distance_mismatch`, `link_bearing_mismatch`, `restricted_access` (`access` lub `motor_vehicle` ∈ {`private`, `no`}).
  5. `camera_against_way_direction`, `boundary_crossing` → tylko `info_flags`. `poor_heading_alignment` z wejścia nie jest przyczyną sama w sobie (próg liczony ponownie).
  6. Kolejność `reasons` deterministyczna (kolejność reguł powyżej), bez duplikatów.
- `link_counts(df) -> dict` — `{"certain", "uncertain", "no_candidate", "total", "missing_heading"}` (ostatnie = suma `heading_missing`; zdjęcia bez kandydata też liczą się do `missing_heading` jeśli heading NaN).
- `assess_sign_links(nearest, signs, osm_2180, th) -> DataFrame` — mapowanie schematu `signs/nearest_osm.csv`: `heading_diff_deg` → `bearing_diff`, `match_flags` → `candidate_flags`, brak `match_method` (traktuj jak `osm_source_reference`), heading = `compass_angle` z `signs.csv`. Wiersze z `source == "osm_api"` albo flagą `outside_standard_25m` → `status="evaluation_only"`, `reasons=["evaluation_only"]` (bez liczenia geometrii). Pozostałe przez tę samą logikę co `assess_links`.
